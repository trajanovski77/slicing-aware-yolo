# Slicing-Aware YOLO Inference for Small Objects in High-Resolution Aerial Imagery

Code and result matrix for a controlled, inference-only comparison of native full-image
versus slicing-aware (tiled) YOLO inference on high-resolution aerial imagery. Three
medium detectors (YOLOv8m, YOLO11m, the NMS-free YOLO26m) are evaluated without any
retraining on the original, untiled DOTA-v1.5 validation scenes and on a low-resolution
ship set, with both regimes scored by one COCO evaluator on original-image coordinates.

The paper (TELFOR 2026, under review) reports the accuracy, latency, duplicate and
seam diagnostics produced by this pipeline; every number in it is generated by the
scripts below and stored under `results/`.

## Two evaluation caps you must lift on dense aerial imagery

Two silent defaults truncate dense-scene results and are lifted here; leaving either at
its default changes every headline number:

- **Ultralytics `max_det`** defaults to 300 detections per image, below the ground-truth
  count of the 48 densest DOTA-v1.5 validation scenes (which hold 67 % of all boxes).
  All inference in this study runs with `max_det: 10000` (per image for native, per tile
  for sliced; see `configs/slicing/*.yaml`).
- **pycocotools `maxDets`** defaults to 100 detections per image and class; 112
  image-class cells in DOTA-v1.5 val exceed that, and the default caps COCO recall at
  0.405. The evaluator here raises it to 10,000 (`src/eval/coco_eval.py`, run through
  `faster-coco-eval`; passing 100 reproduces stock pycocotools bit for bit).

## Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt      # torch/ultralytics, pycocotools, faster-coco-eval
pip install -e ".[sahi]"             # optional, only for the SAHI cross-check
```

## Data and weights

- **DOTA-v1.5**: the *original untiled* validation images and `labelTxt` HBB annotations
  under `data/raw/DOTA` (the study slices these; pre-tiled crops defeat its purpose).
- **Ship set**: the Kaggle *Ships/Vessels in Aerial Images* dataset (YOLO format) under
  `data/processed/ships`.
- **Weights**: detector checkpoints trained on 1024 px DOTA tiles (16 classes) and on the
  ship training split at 640 px (1 class); paths configured in `configs/slicing/*.yaml`.

## Reproduce

```bash
scripts/run_slicing.sh prepare_gt    # COCO GT per dataset (CPU)
scripts/run_slicing.sh predict       # native {640,1024,1536} + sliced {512,640,1024}x{0.10,0.20}
scripts/run_slicing.sh eval          # uncapped COCO scoring + P/R/F1 at conf 0.25
scripts/run_slicing.sh diagnostics   # duplicate rate + near-seam false positives
scripts/run_slicing.sh benchmark     # median per-image latency, interleaved, quiet GPU
scripts/run_slicing.sh report        # tables + figures
python scripts/analysis_strata.py dota-sizes ship-sizes ship-strata dota-density
python scripts/bootstrap_ci.py --model yolo11m_dota --reps 300
python scripts/paper_ieee_assets.py --out-dir paper_assets_ieee   # paper table + figure
python scripts/sahi_crosscheck.py --config configs/slicing/dota.yaml \
    --model yolov8m_dota --tile 640 --overlap 0.20 --limit 50     # correctness anchor
```

Latency methodology: batch 1, 100 validation images drawn with a fixed seed, ten untimed
warm-up passes, every detector x variant pair timed once per image with the cycle order
rotating between images, and the card's concurrent utilisation recorded beside the
timings (`--interleave`). Take the sweep on an otherwise idle GPU.

## Layout

- `src/` inference (native + sliced with cross-tile merge), COCO evaluation, diagnostics,
  reporting; the slicing geometry and matchers are pure functions with unit tests (`pytest -q`).
- `scripts/` the pipeline stages and analyses listed above.
- `configs/` dataset and sweep definitions.
- `results/` the published matrix: accuracy (`tables/*_slicing_metrics.csv`), diagnostics,
  size/density strata, paired-bootstrap intervals, and latency (`metrics/speed/`).
